# ERP 업무 RPA 요건정의

고객사 RPA 도입에 앞서 **자동화 대상 업무를 분해하고 요건정의서로 정리한 기록**이다.
대상 시스템은 Microsoft Dynamics 365(D365)와 Excel이다.

고객사 건이라 요건정의서 원본·업무 화면 녹화·실데이터는 올리지 않는다.
**어떻게 분해했고 무엇이 막혔는지**를 담았다.

| 한눈에 | |
|---|---|
| 범위 | 두 팀의 D365·Excel 업무 **7건**을 자동화 과제로 분해 |
| 방법 | 업무 이름이 아니라 **입력 경로가 갈리는 지점**으로 자름(SO/PO 등록 1건 → 3패턴). 업무 화면 녹화를 캡처해 과제당 8~19장으로 프로세스 복원 |
| 막힌 것 | 담당자 확인이 안 된 2건은 추정으로 채우지 않고 빈칸 + "확인 필요"로 제출. 필요한 자료를 요청 항목으로 정리해 되돌림 |
| 기술 | RPA 요건정의 · Microsoft Dynamics 365 · Excel |

---

## 다룬 과제 7건

두 팀의 업무를 과제 단위로 쪼갰다.

| 팀 | 과제 | 성격 |
|---|---|---|
| 경영관리 | SO/PO 등록 패턴 1 — 매입·매출등록 (직송, 무상샘플) | D365 입력 자동화 |
| 경영관리 | SO/PO 등록 패턴 2 — 매입등록 (재고) | D365 입력 자동화 |
| 경영관리 | SO/PO 등록 패턴 3 — 매출등록 (재고, 커미션) | D365 입력 자동화 |
| 경영관리 | 회계전표입력 | D365 입력 자동화 |
| 경영관리 | SalesReport 메일링 | 추출·가공·발송 |
| 환경 | Inventory 가공 | 추출·가공 |
| 환경 | Sales Report 가공 | 추출·가공 |

같은 "SO/PO 등록"이라도 **직송·재고·커미션에 따라 입력 경로가 달라서 3개 패턴으로 분리**했다.
하나로 묶으면 분기 조건이 요건서 안에서 폭발한다.
