# ERP 업무 RPA 요건정의

고객사 RPA 도입 전에 ERP·Excel 업무를 자동화 과제로 나누고 요건정의서를 작성한 작업이다.

> 회사 업무로 수행한 작업이라 요건정의서 원본·업무 화면·데이터는 올리지 않고, **어떻게 일했는지만** 적었다.

| 개요 | |
|---|---|
| 역할 | 요건정의 담당(업무 분석 · 과제 분해 · 요건정의서 작성 · 자료 요청) |
| 범위 | 두 부서의 ERP(Microsoft Dynamics 365)·Excel 업무 7건 |
| 기술 | RPA 요건정의 · Microsoft Dynamics 365 · Excel |

---

## 한 일

### 1. 과제 단위 나누기

- 업무 이름이 아니라 **입력 경로가 갈라지는 지점**을 기준으로 과제를 나눴다.
- 이름은 같은 "매입·매출 등록"이지만 거래 유형에 따라 시작 트리거와 등록 순서가 달라 3개 패턴으로 분리했다. 하나로 묶으면 요건서 안의 분기가 감당할 수 없이 늘어난다고 판단했다.
- 입력형 과제(ERP에 무엇을 넣는가)와 추출·가공형 과제(어떤 기준으로 집계해 보내는가)는 요건서 구성 자체를 다르게 잡았다. 실적 리포트 과제에는 계획 수치와 실적의 자동 비교 요구가 붙어, 비교 기준 축을 정리했다.

### 2. 화면 녹화로 프로세스 복원

- 담당자 설명만으로는 클릭 순서와 필수 입력값을 알 수 없어, 업무 화면 녹화를 받아 단계별로 캡처하고 번호를 붙여 요건서에 넣었다(과제당 8~19장).
- 설명에서 빠진 팝업 확인, 탭 전환 같은 단계를 화면에서 찾아냈다. 개발자가 요건서만으로 화면 요소를 특정할 수 있게 했다.
- 입력 항목이 많은 전표 입력 업무는 녹화 없이는 필드 목록조차 확정할 수 없어 이 방식이 특히 필요했다.

### 3. 확정하지 못한 것을 확정한 것처럼 쓰지 않기

- 담당자 확인이 잡히지 않은 2건은 추정으로 채우지 않고 **빈칸과 "확인 필요"로 제출**했다. 추정으로 쓴 요건으로 개발에 들어가면 전부 다시 만들게 된다.
- 공통으로 부족했던 것(실제 데이터 양식, 화면 기준 필수 입력값, 설명과 화면의 일치 여부)을 정리했다.
- Excel 필터·수식 기준, 실제 문서 기준 정합성 확인, 검증용 표준 데이터 확보를 **요청 항목**으로 만들어 고객사에 되돌렸다.

## 배운 것

- RPA는 화면과 데이터 형식에 의존하므로 **검증 데이터 확보도 요건의 일부**다.
- 과제를 나누는 기준을 먼저 정하면 이후 공수 산정과 개발 범위 협의가 쉬워진다.
