# 2. 막힌 지점

요건정의서에 **확정하지 못한 것을 확정한 것처럼 쓰지 않았다.**
미확인 항목은 미확인으로 남기고 무엇이 필요한지 적었다.

## 업무 내용 자체를 확인받지 못한 과제

환경팀 과제 2건(Inventory 가공, Sales Report 가공)은
담당자 확인이 잡히지 않아 **업무 내용과 프로세스를 비워 둔 채 제출**했다.

추정으로 채우면 그럴듯한 문서가 나오지만, 그 문서로 개발이 들어가면
전부 다시 만들게 된다. 빈칸으로 두고 "확인 필요"를 남기는 편이 정직하고 싸다.

## 공통으로 부족했던 것

과제 전반에서 같은 문제가 반복됐다.

| 부족한 것 | 그래서 생기는 문제 |
|---|---|
| **실제 업무 데이터 양식** | 필드 매핑과 입력값 정의를 할 수 없다 |
| 상세 화면 기준 필수 입력값 | 어디까지 채워야 저장되는지 모른다 |
| 업무 프로세스와 시스템 화면의 일치 여부 | 설명과 실제 화면이 어긋나는 구간을 못 찾는다 |

## 요청으로 정리해 되돌린 것

막힌 것을 그냥 두지 않고 **무엇을 주면 풀리는지**를 요청 항목으로 정리했다.

- SalesPurchaseReport 파일 안의 **Excel 필터 기준과 셀 수식 기준** 확보
- **실제 문서 기준**으로 정합성 확인
- 자동화 검증에 쓸 **표준 데이터** 확보

RPA는 화면 좌표와 데이터 형식에 의존하므로,
검증용 표준 데이터가 없으면 "되는 것처럼 보이는" 상태로 넘어가기 쉽다.
자동화 대상 업무의 요건정의에서는 **검증 데이터 확보가 요건의 일부**다.
